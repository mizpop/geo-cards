# GeoChecker

画像と説明から「どの国・地域で見られるか」を覚えるための、Quizlet 風の暗記カードアプリです。

- **暗記カード**: クリック / スペースキーでめくり、← → で移動。地域で絞り込みとシャッフルができます
- **クイズ**: 出題する地域・問題数・回答方式（4択 / 国名を入力）を選べます。間違えた問題だけ再挑戦もできます
- **検索**: 国名・地域名（日本語・英語）で、該当するカードをタイル状に一覧表示。クリックで拡大します
- **編集**（編集者のみ）: カードの追加・編集・削除。画像はファイル選択、ドラッグ＆ドロップ、クリップボードからの貼り付け（ボタンまたは Ctrl+V）に対応しています。国は地域ごとのリストから選びます（複数可）
- **バックアップ**: 画像込みの JSON を書き出し・読み込みできます
- **カテゴリー**: ボラード・シェブロンなどのカテゴリーで色分けします。カードタブの「🏷 カテゴリー管理」から、追加・名前変更・色変更・並べ替えができます。暗記カード・クイズ・検索・地図で絞り込めます
- **地図**: カードがある国を色で塗り分けて表示します。国をクリックするか拡大すると、その場所にカードのサムネイルが現れ、右側に一覧が出ます（地図: Leaflet / © OpenStreetMap contributors、国境データ: Natural Earth（world-atlas））
- **国の基本情報**: 地図の右側パネルで国名をクリックすると表示されます。国旗、言語（クリックで見分け方を表示）、国別ドメイン、通行方向、国際電話番号、首都、通貨、隣接国。国データは [mledoze/countries](https://github.com/mledoze/countries)（ODbL）から生成しています
- **国のメモ**: 国の詳細画面で、国ごとにメモを書けます（編集者のみ。入力が止まると自動保存）。地図の右パネルとプレビューの吹き出しにも表示されます。Supabase を使っている場合は `supabase/setup.sql` をもう一度 Run するとメモ用のテーブルが追加されます
- **画像編集・関連カード**: 編集画面の「🎨 画像編集」でトリミングと書き込み（表面に焼き込み / 裏面だけに表示する印）ができ、カードに関連カードを付けられます。Supabase では `supabase/card-extras.sql`（または `setup.sql` の再実行）で列を追加してください
- **学習記録の同期**: 設定の「🔄 学習記録の同期」で、「覚えた / まだ」・連続日数・毎日の回数・タイムアタックの自己ベストを、PC とスマホなどで共有できます。1 台目で「コードを作る」を押し、表示された 20 文字の引き継ぎコードを 2 台目に入力します。記録は各端末に残したまま、新しい方・大きい方を採ってマージします（Supabase の SQL Editor で `supabase/progress-sync.sql` を一度実行してください）。コードを知っている人だけが、そのコードの記録を読み書きできます
- **暗記に参考写真**: 暗記の「📷 写真も」で、GeoHints の参考写真（約 1,000 枚）も「覚えた / まだ」で復習できます（復習では、まだ見ていない写真は 1 日 10 枚ずつ増えます）
- **浮かぶウィンドウ（PC のみ）**: カード・国・参考写真の詳細は、ストリートビューと同じ浮かぶウィンドウで開き、後ろの地図や一覧もそのまま操作できます。ヘッダーのドラッグで動かし、角で大きさを変え、ダブルクリック（または ⤢）で拡大、「—」でヘッダーだけに縮小できます。位置と大きさは覚えます（Esc で閉じる・ウィンドウの中では ← → でカードの前後へ）。ウィンドウを画面の左右のはしへドラッグして離すと、画面を分割できます（ヘッダーは分割せず、その下の部分だけ。左右に 1 つずつ、合わせて 2 つまで置け、そろうと 3 等分になります。境目のドラッグで幅を変え、ヘッダーをドラッグして外すと元に戻ります。タブを切り替えても分割は保たれます）。ストリートビューのパネルも同じです。スマホなど狭い画面では、これまでどおりのモーダルです
- **地図の右パネルの幅**: 地図と右のパネル（国の情報・一覧）の間の境界線を左右にドラッグして、パネルの幅を変えられます（ダブルクリックで元に戻す・← → キーでも調整。幅は覚えます）。隣接国が 3 行以上になるときは 2 行までに折りたたみ、「他 N か国 ▾」で開閉できます
- **地図のサムネイル**: 地図を縮小して数字だけが出ているときも、数字をクリックすると、その国のサムネイルが出ます（カーソルがサムネイルから離れると消え、地図の移動・拡大でも消えます。その国の情報も右のパネルに出ます）
- **都市の検索**: 地図の検索バーに、都市の名前（ワルシャワ・パリ・Tokyo など）を入れると、下に都市の候補（人口つき）が出ます。選ぶ（矢印キー＋Enter・クリック）と、その都市へ移動して目印を置き、その国の情報を右パネルに出します。目印は、✕・Esc・地図の他の場所をクリックで消せます。「東京」「大阪」「京都」のように漢字だけの名前は、候補には出ないので、Enter（または「OpenStreetMap で探す」）で探します（「京都」は「京都市」も探します）。Enter は、候補が更新されるのを待たず、入力した言葉そのもので、すぐに探して移動します（漢字の名前は、「京都市」「東京都」のように「市」「都」を付けた形も同時に探すので、約 0.3 秒です。見つからないときだけ OpenStreetMap で探します）。候補と目印には、日本語の名前に続けて、英語と現地の言語の名前も表示します（例: ワルシャワ · Warsaw · Warszawa、カイロ · Cairo · القاهرة。同じ綴りは 1 つにまとめます）。ハイフン・スペース・ピリオドは無視して探します（`saint-denis` と `Saint Denis` は同じ）。ローマ字でも探せます（`tokyo`・`osaka`・`oosaka`（長音の書き方）・`kyouto`、外国の都市は `berurin`・`warushawa`・`nyuuyooku` のようにカタカナに直して）。国名はこれまでどおり国へ移動します。候補は [Open-Meteo](https://open-meteo.com/) のジオコーディング、漢字の地名は [OpenStreetMap の Nominatim](https://nominatim.org/)（Enter を押したときだけ、1 秒に 1 回まで）を、どちらもキーなしで使っています
- **再読み込みしても続きから**: ページを再読み込みしても、開いていたタブ・暗記の位置とめくり・絞り込み・クイズの途中（回答済みの問題・残り時間。制限時間つきは、再読み込みの間も時間が進みます）・開いていたカード/国/写真のウィンドウ（縮小・拡大・左右への分割も）・設定・検索・AI アシスタントの会話・地図の位置と目印とストリートビューを引き継ぎます。保存先はそのタブの sessionStorage（`js/session.js`）で、12 時間以内・ログアウトで消えます。対戦は引き継ぎません
- **保存したストリートビュー（ストリートビュータブ）**: ストリートビューのウィンドウ（`js/svwin.js`。地図・参考写真・保存した一覧のどのタブからでも開けて、他のタブに移っても残ります）の **保存** ボタン（編集者）で、その場所を保存します。保存するときに、国（地図の国境から）と大まかな地名（日本語・英語・現地の言語・州や県。OpenStreetMap の Nominatim で）を自動で付けます。ストリートビュータブ（`js/savedsv.js`）で、国・地名で絞り込み、ウィンドウで開く・その場所でカードを作る・削除ができます。カードの編集画面の地名欄の「🧍 保存したストリートビューから足す」で、保存した場所を地名（と国）として足せます。ウィンドウ内の矢印で移動した位置は、Google の埋め込みからは読み取れないので、ウィンドウ内の「Google マップで見る」（今いる地点の URL）から取り込みます（ブラウザ版は、それを右クリック →「リンクのアドレスをコピー」→ ヘッダーの 📋 ボタン。Windows 版アプリは、Electron が埋め込みの中のそのリンクを直接読み取るので、貼り付け不要で、移動した位置を 1.5 秒ごとに自動で追いかけます）。参考写真の詳細の「🧍 ストリートビューをウィンドウで開く」は、その写真の撮影地点（向きつき）をアプリ内のウィンドウで開きます。保存した場所には、自分で名前をつけられます（ストリートビュータブの「✏ 名前」。地名は別の行に残ります）。カードの編集画面の「関連ストリートビュー」で、カードと保存したストリートビューを関連付けられます（カードを開くとボタンから開け、ストリートビュータブにも関連カードが出ます）。Supabase では、`supabase/card-extras.sql`（または `setup.sql`）を実行して `saved_streetviews` の表と、`cards.sv_ids` の列を作ってください（読めるのは全員、書けるのは編集者）
- **カードの地名**: 編集画面の「地名」で、都市・町を検索してカードに追加できます（Enter で一番上を追加。日本語・英語・現地の言語の名前と座標を保存し、その国も自動で追加します）。暗記の裏面・カード詳細・クイズの答え合わせに「📍 ワルシャワ · Warsaw · Warszawa」のように表示し、押すと地図でその場所へ移動して目印を置きます。地名はカードの検索の対象にもなります。Supabase では、`supabase/card-extras.sql`（または `setup.sql`）を実行して、`places` の列を追加してください（実行前は、地名を付けないカードなら今までどおり保存できます）
- **ストリートビュー**: 地図の検索バーの右のアイコンを押すと、ストリートビューのある道路が青い線で表示されます（拡大すると半分の太さ）。道路の近く（250m 以内・画面で 44px 以内）をクリックすれば、いちばん近い道路に寄せて開き、マウスを動かすと開く場所の印が出ます。映像は画面に固定したパネルに表示し、ヘッダーのドラッグで画面のどこにでも動かせ、ダブルクリックで拡大・元の大きさに戻せ、「—」ボタンでヘッダーだけに一時的に縮小できます。パネルの「📍」を押すと、国と場所と Google マップのリンクを入れたカードの作成画面が開きます（画像は作成画面で選びます）。クリックした付近の道路は、縮尺が低くても探して開き、何もない所では開く前に「ありません」と出します。地図は縮尺 18 まで拡大できます。Google マップの埋め込みと、ストリートビューの対応範囲のタイルを、API キーなしで使っています
- **ストリートビュー練習**: クイズの「🧍 ストリートビュー」で、選んだ地域の国からランダムな道路のストリートビューを出題します（4択・国名入力・地図・場所を当てる）。映像は動き回れ、答えるまで場所の名前の表示を隠します。出題は毎回違い、覚え具合には記録しません。パネルの「📍」からは、見つけた場所でカードを作れます
- **低画質版の画像**: カードを保存すると、一覧・地図・関連カード用に小さい低画質版（長辺 480px）も一緒に保存し、大きい画像は詳細・暗記・クイズを開いたときだけ読み込みます（Supabase の転送量の節約）。すでにあるカードは、カードタブの「🖼 軽量画像を作成」で一括で作れます（`supabase/card-extras.sql` の実行が必要）
- **ストリートビュー**: 地図の上のボタン（人のアイコン）を押してから、地図の道路などをクリックすると、その場所の Google ストリートビューが地図の上のパネルに表示されます（パネルはドラッグで移動・端で大きさ変更・⤢で拡大。Esc で閉じる）。API キーなしで使える Google マップの埋め込み表示を使っています
- **AI アシスタント**: 上のバーの ✨ ボタンで開くチャットです。質問に出てくる国・手がかりの種類（ボラード・シェブロンなど）から、関係するカード・参考写真の解説・国ごとの地図のデータ・言語・学習の記録だけを選んで AI（Google の Gemini・無料枠。混み合っているときは Cloudflare の AI）に渡して答えてもらいます。答えの中の [C1]（カード）・[P1]（写真）・国名の印を押すと、その項目が開きます。画像を付けて「この写真はどこの国？」と聞くこともでき、カード詳細・参考写真の画面の「✨ AI に質問」からは、そのカード・写真を見せて質問できます。使うには、下の「AI アシスタントの設定」が必要です
- **言語タブ**: 言語の一覧と、看板に出てくる文字（ダイアクリティカルマーク付きの文字・キリル文字など）を選んで言語を絞り込めます
- **メモ（チャット形式）**: 画面右下のボタンで開閉。どの画面からでも書けて、日付・時刻付きで履歴が残ります（Enter で送信、Shift+Enter で改行）。ログイン中の人は誰でも書け、消せるのは書いた本人と編集者です。Supabase では `supabase/setup.sql` を再実行するとテーブルが追加されます

構成: 静的な HTML/JS（ビルド不要）＋ Supabase（DB・画像ストレージ・ログイン）。クレジットカードは不要です。

## 0. まずローカルで試す（デモモード）

`js/config.js` が未設定の間は、データをブラウザ内だけに保存する「デモモード」で動きます。

```bash
cd geo-cards
python3 serve.py
# ブラウザで http://localhost:8000 を開く
```

※ `index.html` をダブルクリックして直接開くと動きません（ES モジュールの制約のため）。必ずサーバー経由で開いてください。
※ `serve.py` はブラウザにキャッシュさせないサーバーです。`python3 -m http.server` だと、更新後に古いファイルが混ざって起動しないことがあります（その場合は Ctrl+Shift+R）。

## 1. Supabase の準備（10 分ほど）

1. https://supabase.com で GitHub アカウントなどでサインアップし、**New project** を作成します
   - Region は `Northeast Asia (Tokyo)` がおすすめです
   - Database Password は自動生成で構いません（このアプリでは使いません）
2. 左メニューの **SQL Editor** を開き、`supabase/setup.sql` の中身を全文貼り付けて **Run** します（アプリを更新したときも、もう一度 Run すれば新しい項目が追加されます。既存のデータは消えません）
3. **新規登録を禁止する**（重要）
   - **Authentication → Sign In / Providers**（または Settings）で **Allow new users to sign up** を **OFF** にします
   - これを OFF にしないと、誰でもアカウントを作ってカードを閲覧できてしまいます
4. **アカウントを 2 つ作成する**: **Authentication → Users → Add user → Create new user**
   - **閲覧用**: メールアドレスは何でも構いません（例: `viewer@example.com`）。パスワードがそのまま「閲覧パスワード」になります。**Auto Confirm User** にチェックを入れてください
   - **編集者（あなた）**: 自分のメールアドレスと強めのパスワードで作成し、同じく **Auto Confirm User** にチェックを入れます
5. `supabase/add-editor.sql` のメールアドレスを自分のものに書き換えて、SQL Editor で **Run** します
6. **Project Settings → API Keys**（または Data API）で以下の 2 つを確認します
   - Project URL（`https://xxxx.supabase.co`）
   - `anon` キー、または `publishable` キー（ブラウザに置いてよい公開用のキー。**`service_role` / `secret` キーは絶対に使わないでください**）
7. `js/config.js` に記入します

```js
export const CONFIG = {
  SUPABASE_URL: 'https://xxxx.supabase.co',
  SUPABASE_KEY: 'eyJ...（または sb_publishable_...）',
  VIEWER_EMAIL: 'viewer@example.com',   // 手順 4 で作った閲覧用アカウント
  BUCKET: 'card-images',
};
```

ローカルで開き直すと、ログイン画面が表示されます。
- 閲覧パスワードを入力すると、閲覧のみ（暗記カード・クイズ・検索）を使えます
- 「編集者としてログイン」からパスワードを入力すると（メールアドレスは `js/config.js` の `EDITOR_EMAIL` に固定してあります。変えるときはここを書き換えます）、カードタブで追加・編集・削除もできます

### セキュリティについて
- 権限は Supabase の RLS で、データベース側で制御しています。閲覧用アカウントでは、API を直接叩いても編集できません
- 画像は非公開のバケットに保存し、ログイン中のユーザーにだけ有効期限付きの URL を発行します
- 閲覧パスワードを変えたいときは、Authentication → Users で閲覧用ユーザーのパスワードを変更します

## 2. 公開する

### Cloudflare Pages（おすすめ・帯域無制限）
1. このフォルダを GitHub リポジトリに push します（Private で構いません）
2. Cloudflare ダッシュボード → **Workers & Pages → Create → Pages → Connect to Git** でリポジトリを選びます
3. Build command は **空欄**、Build output directory は `/` のままで **Deploy** します
- Git を使わない場合は、**Upload assets** でフォルダをドラッグ＆ドロップしても公開できます

### GitHub Pages
1. リポジトリを **Public** で作成して push します（無料プランでは Public のみ対象）
2. **Settings → Pages → Branch: main / (root)** を選んで保存します

どちらの方法でも、`js/config.js` のキーが公開されます。これは想定どおりで、`anon` / `publishable` キーは公開前提のキーです。データは RLS とログインで保護されています。

### AI アシスタントの設定（Cloudflare Pages・無料）
AI アシスタントは、次の 2 つの無料の AI を使います。どちらか一方だけでも動きますが、**両方**にしておくと、片方が混み合っている・無料枠の上限のときに、自動でもう片方に切り替わります。
- **Google の Gemini API（無料枠）**: 答えの質が高く、画像も読めます。API キーが要ります。
- **Cloudflare の Workers AI（予備）**: キーは要らず、1 日 10,000 ニューロンまで無料です（1 回の質問で約 100〜200 ニューロン使うので、1 日に 50〜100 回ほど。モデルは Llama 4 Scout）。

API キー・バインディングはブラウザには渡さず、Cloudflare Pages の関数（`functions/api/ask.js`）だけが持ちます。

**Gemini の設定**
1. [Google AI Studio](https://aistudio.google.com/apikey) で Google アカウントにログインし、**Create API key** で API キーを作成します（クレジットカードは不要）
2. Cloudflare ダッシュボード → 対象の Pages プロジェクト → **Settings → Variables and Secrets** で、`GEMINI_API_KEY` を **Secret** として追加します（Production）

**Cloudflare AI（予備）の設定**
1. 同じ **Settings** の **Bindings → Add → Workers AI** を選びます（Production）
2. **Variable name** を `AI` にして保存します

最後に、**Deployments** から最新のデプロイを再デプロイします（次の push でも反映されます。変数・バインディングは、設定したあとのデプロイから有効になります）。

必要に応じて、**Variables** に次の変数も追加できます。

| 変数 | 意味 |
|---|---|
| `CHAT_MODEL` | 自動のときに最初に試す Gemini のモデル。初期値は `gemini-3.8-flash` |
| `CHAT_FALLBACK_MODELS` | Gemini が混み合っている（503）・回数の上限（429）のときに、順に切り替える Gemini のモデル（カンマ区切り）。初期値は `gemini-3.5-flash,gemini-3.5-flash-lite,gemini-3.1-flash-lite` |
| `CHAT_EFFORT` | 考える深さ（`minimal` / `low` / `medium` / `high`）。初期値は `low`（速い）。Gemini 3 以降のモデルだけに効きます |
| `CHAT_EDITORS_ONLY` | `1` にすると、編集者のアカウントだけが使えます（閲覧用アカウントでは使えない）。無料枠の回数を守りたいときに |
| `CHAT_ALLOW_ANON` | `1` にすると、ログインなしでも使えます（デモ用。公開サイトでは設定しないでください） |

- **モデルの選択**: チャットの上の欄で、使うモデルを選べます（選んだモデルは、この端末に覚えます）。**自動**は、Gemini の `CHAT_MODEL` を先に試し、混み合っている・上限のときは、Gemini の別のモデル → Cloudflare AI の順に切り替えます（切り替わったときは、答えの下にそう表示されます）。モデルを手動で選んだときは、そのモデルだけを使い、混み合っていても勝手に切り替えません。選べるのは、Gemini の 3 系の Flash・Flash-Lite と、Cloudflare AI です。
- ログインしている人だけが使えます（サーバー側で Supabase のログインを確認してから送ります）。
- **無料枠の注意**: Google の規約では、Gemini の無料枠に送った内容は Google のサービスの改善に使われることがあります。質問と、関係するカード・写真の情報（説明・解説・画像など）が送られるので、見られて困る内容は書かないでください。気になる場合は、Gemini を使わずに Cloudflare AI だけにするか、Google Cloud の課金を有効にした有料枠（内容は改善に使われません）に切り替えられます。
- Gemini の無料枠には、1 分あたり・1 日あたりの回数の上限があります（モデルごとに違い、[AI Studio](https://aistudio.google.com/rate-limit) で確認できます）。1 日の上限は、日本時間の夕方（16〜17 時ごろ）にリセットされます。Cloudflare AI の上限は、毎日 UTC 0 時（日本時間の朝 9 時）にリセットされます。
- 1 回の質問で送る資料は約 1 万文字までです。
- ローカルでの画面の確認は、`MOCK_ASK=1 python3 serve.py` で起動すると、AI には接続しない仮の答えが返ります。

## 3. 一時停止を防ぐ（Supabase 無料プランの仕様）

無料プランのプロジェクトは、7 日間アクセスがないと一時停止します（データは消えず、ダッシュボードから再開できます）。

GitHub にリポジトリを置いた場合は、`.github/workflows/keepalive.yml` が週 2 回自動でアクセスします。
- リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で、`SUPABASE_URL` と `SUPABASE_KEY` を登録してください
- **Actions** タブで **Supabase keepalive → Run workflow** を実行すると、動作を確認できます

### Windows 版の自動公開（GitHub Actions）

`electron/` の中を変えて `main` に push すると、`.github/workflows/desktop-release.yml` が Windows 上でインストーラーをビルドして、公開リポジトリ `mizpop/geochecker-releases` の Releases に自動で公開します（`electron/package.json` の `version` を上げておくと、新しい版として公開され、インストール済みのアプリが起動時に自動で更新します）。Actions の画面から手動で実行もできます。

**最初に 1 回だけ**、次の準備が必要です（トークンはあなた自身が作ります。私や他の人には渡さないでください）:

1. GitHub の **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
   - Repository access: **Only select repositories** → `geochecker-releases` だけ
   - Permissions → Repository permissions → **Contents: Read and write**
2. このリポジトリ（`geo-cards`）の **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `RELEASES_TOKEN` / Secret: 作ったトークン

手元でビルドして公開したいときは、`electron/` で `GH_TOKEN`（同じトークン）を環境変数に入れて `npm run release` を実行します。
